# GitHub 源码准备说明

源码 ZIP 是从明确文件清单导出的运行源码，不是整个学习文件夹的备份。原始教学章节和学习记录仍保留在开发工作区。

## 本地从源码构建

准备 Docker Desktop 的 x64 Linux 容器环境，解压源码包，运行 **从源码构建.cmd**。首次会联网构建应用、构建附带完整源码的 MinIO、拉取 PostgreSQL 和 Redis，并下载与校验四个固定本地模型文件。完成后运行 **安装并启动.cmd**。源码构建不需要宿主机安装 Python 或 Node.js。

离线安装包已经含有这些镜像与模型，直接安装即可，无需从源码构建。两种包的本地启动入口相同。

## 上传边界

- GitHub 仓库放源码包解压后的内容。保留 Dockerfile、锁文件、本地安装入口、第三方声明及 MinIO 对应源码。
- 镜像和模型是安装包资产，通过仓库 Releases 作为版本附件发布；不要把它们加入 Git 源码历史。
- `.env`、运行数据、备份、日志、浏览器验收图片、账号与教学文件不在源码包内。生成配置后也不要上传。
- `.github` 未包含自动部署。将源码上传 GitHub 不会自动发布网站或触发付费模型。
- 本项目自行编写的应用代码采用 MIT 授权，署名 nigu666；再分发时保留 LICENSE。教程参考、第三方代码、镜像和模型分别保留原作者版权与各自授权，详见 NOTICE 和 THIRD_PARTY_NOTICES.md。

## 结构

```text
backend/app、migrations     API、Worker、迁移与本地修图实现
frontend/src               React 页面与悬浮画布
Dockerfile                 多阶段构建，运行阶段不含 Node
deployment/local           Compose、中文入口、模型校验与配置模板
infrastructure/minio       MinIO 构建方法与对应版本记录
third_party                第三方许可、MinIO 完整源码和依赖清单
```

普通源码构建需要访问 Docker 镜像源、Python/Node 依赖源、GitHub 和 Hugging Face。模型只下载数据权重，核对 SHA-256 后使用，不执行远程模型仓库代码。
